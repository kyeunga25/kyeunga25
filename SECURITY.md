# 安全政策 / Security Policy

## 私密回報 / Private reporting

如發現個人檔案或入口連結可能導致冒充、惡意重新導向、供應鏈修改或私人資料外洩，
請使用 GitHub Security 頁面的私人漏洞回報或私人 security advisory。不要在公開
issue 或 PR 貼出 credential、私人資料或可直接利用的內容。

Report impersonation, malicious redirects, supply-chain changes, or privacy
exposure through GitHub's private vulnerability reporting or a private security
advisory. Do not publish credentials, personal data, or actionable exploit
details in public issues or pull requests.

## 範圍 / Scope

- 安全修正以預設分支最新原始碼為準。
- 產品版本、成熟度與 live 連結必須以公開證據核對，不可把 preview 當作 production。
- Profile 不應公開 secret、私人路徑、帳戶／部署識別資料或非公開產品細節。
- 外部連結及 Actions 必須經驗證；Actions 應固定完整 commit SHA 並維持最小權限。

Security fixes target the latest default-branch source. Product status and live
links must be evidence-backed, while secrets, private paths, deployment
identifiers, and non-public product details remain outside the profile.
